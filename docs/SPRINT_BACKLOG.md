## 1. 자체 백엔드 구현

**목표**

로그인, 데이터베이스, 사진 저장은 Supabase 를 그대로 쓰고, 그 앞에 직접 만든 API 서버를 둡니다. 앱은 Supabase 대신 이 서버에 요청하고, 서버가 검증한 뒤 데이터베이스를 읽고 씁니다.

**왜 이 방식인가**

틀리면 위험한 로그인과 보안은 검증된 것을 계속 쓰면서, 서버 로직만 내 코드로 가져올 수 있습니다. 기능을 하나씩 옮기므로 작업 중에도 앱이 멈추지 않습니다.

**기술** (2026-11-13 확정)

- 언어: JavaScript (화면과 같은 언어). 흐름에 익숙해지면 TypeScript 로 전환
- 프레임워크: Hono
- 위치와 배포: 같은 저장소의 `api/` 폴더, Vercel 서버 함수. 항상 켜진 서버가 필요해지면 Railway 나 Fly.io 로 이전
- 로그인 확인: 앱이 보내는 Supabase 로그인 토큰을 요청마다 Supabase 에 물어 확인 (`auth.getUser`)
- DB 접근: 요청한 사용자 신분으로 접근해 RLS 규칙이 그대로 적용되게 함. 서비스 키는 꼭 필요한 기능에만
- 로컬 개발: Hono 앱을 로컬 Node 서버(포트 8787)로 띄우고, 개발 서버가 `/api` 요청을 넘겨줌
- 작업 방식: `feat/backend` 브랜치에서 작업하고 Vercel 미리보기 주소에서 확인한 뒤 main 에 합침

**스프린트 1** (진행 중): 1단계와 2단계

- 진행 (2026-11-15): API 서버 뼈대, 토큰 확인 미들웨어, `GET /api/me` 완료
- 진행 (2026-11-16): 공지 주소 `GET /api/announcements/active` 와 앱의 `fetchActiveAnnouncement` 연결 완료 (Supabase 를 직접 부르지 않음). 남은 일은 미리보기 배포 확인, main 에 합치기, 공지 테이블의 직접 접근 닫기는 6단계에서
- 진행 (2026-11-19): 3단계(운동 시작과 완료 검증) 중 서버 주소 `POST /api/workouts/start`, `POST /api/workouts/complete` 완료. 3-3 앱의 `startWorkoutSession`, `completeWorkout` 을 이 주소로 연결 완료 (로그인 토큰을 실어 보냄). 남은 일은 미리보기 배포에서 로그인한 채 운동 완료 확인, main 에 합치기

- 만들 주소: `GET /api/announcements/active` (누구나), `GET /api/me` (로그인 필수, 토큰 확인 연습용)
- 새 서버가 실패하면 공지 배너만 안 보이고 앱은 정상 동작 (예전 방식으로 대신 요청하지 않음)
- 완료 기준: 배포된 앱이 공지를 새 서버에서 받아 오고, 로그인 안 한 요청과 한 요청이 각각 맞게 처리됨

**단계**

| 단계 | 할 일                               | 앱에서 바뀌는 함수                           | 지금 쓰는 서버 기능                                      |
| ---- | ----------------------------------- | -------------------------------------------- | -------------------------------------------------------- |
| 1    | API 서버 뼈대, 토큰 검증, 배포      | 없음                                         |                                                          |
| 2    | 공지 조회 옮기기 (전체 흐름 확인용) | `fetchActiveAnnouncement`                    | `announcements` 테이블                                   |
| 3    | 운동 시작과 완료 검증 옮기기        | `startWorkoutSession`, `completeWorkout`     | `start_workout`, `complete_workout`                      |
| 4    | 그룹 현황과 리더보드 집계 옮기기    | `fetchGroupStatus`, `fetchGroupWorkoutDates` | `get_group_profiles`, `group_members`, `workouts` 테이블 |
| 5    | 응원과 알림 옮기기                  | `sendCheer`, `notifyCheer`                   | `send_cheer`, `notify-cheer` 함수                        |
| 6    | 옮긴 기능의 Supabase 직접 접근 닫기 | 없음                                         | RLS 정책, 함수 권한                                      |

**완료 기준**

- 단계마다 단위 테스트와 DB 보안 테스트(`npm run test:db`)가 통과한다.
- 옮긴 기능은 앱에서 Supabase 를 직접 부르지 않고, 직접 부르면 거절된다(6단계).
- 화면 코드는 바뀌지 않는다. 바뀌는 곳은 `src/server/api.js` 뿐이다.
- `docs/API.md` 에 새 서버의 주소와 요청 형식을 적는다.

**주의할 점**

- 서버 비밀 키(Supabase 서비스 키)는 Vercel 환경 변수에만 둔다. 저장소와 `.env` 에는 넣지 않는다.
- 옮기는 동안은 같은 기능이 두 경로(직접, 서버 경유)로 열려 있다. 단계를 끝낼 때마다 6단계처럼 직접 경로를 닫는다.

## 2. 플레이스토어 등록

웹앱을 안드로이드 앱으로 감싸서 올립니다. 화면 코드는 그대로 씁니다.

- 방식: TWA(Trusted Web Activity). 지금 웹앱을 그대로 여는 가장 가벼운 방법 (Bubblewrap 또는 PWABuilder 로 생성)
- 준비물: 구글 개발자 계정(1회 25달러), 앱 아이콘과 스토어 스크린샷, 개인정보 처리방침 주소
- 해야 할 일: 앱 패키지 생성, 도메인 소유 확인 파일(`assetlinks.json`) 추가, 스토어 등록 정보 작성, 내부 테스트 후 출시
- 이미 갖춘 것: 회원 탈퇴(계정과 데이터 삭제), 신고와 차단, 개인정보 처리방침

## 3. 출시 전 권리 확인

- **푸앙이 캐릭터**: 중앙대학교 캐릭터입니다. 공개 배포 전에 사용 규정을 확인하거나 이스터에그를 뺍니다(`src/lib/easterEggs.js`).
- **운동 영상**: 지금은 외부 YouTube 재생목록을 씁니다. 사용 조건을 확인하거나 6번(자체 3D 영상)으로 바꿉니다.

## 4. 메일 발신 주소 교체

가입 인증, 비밀번호 재설정 메일이 지금은 개인 Gmail 로 나갑니다. 서비스 전용 계정을 만들고 Supabase 의 SMTP 설정에서 주소와 앱 비밀번호만 바꿉니다. 사용자가 늘면 Resend 같은 메일 서비스로 옮깁니다(Gmail 은 하루 약 500통 제한).

## 5. 헬스장 운동 루틴

운동 장소 선택에서 "헬스장에서"가 준비 중으로 막혀 있습니다. 루틴을 만든 뒤 `src/components/WorkoutPlaceModal.jsx` 에서 버튼의 `disabled` 를 풀고 이동할 화면을 연결합니다.

## 6. 자체 3D 운동 영상

외부 YouTube 영상을 Blender 로 만든 3D 영상으로 바꿉니다. 파이프라인은 `prototypes/situp-render/` 에 있습니다.

- 완료: 렌더 파이프라인, 시제품 영상(외부 모델로 윗몸일으키기 남성, 다리 들기 남성과 여성)
- 방향 (2026-11-15): 출시용은 외부 모델 대신 직접 만든 근육 해부도 스타일 모델로 만듭니다. 참고 앱은 Fleek 이고, 그 운동에 쓰는 근육만 브랜드 빨강으로 칠합니다.
- 남은 일 (순서대로)
  1. 자체 모델 만들기 (MPFB 로 남성부터)
  2. 근육 부위 나누기와 강조 색
  3. 다리 들기 하나로 품질 확인
  4. 여성 모델과 30일치 영상
  5. 설정에서 남녀 모델 선택, 앱에 영상 연결
- 자세한 방법은 [인수인계 안내](HANDOVER.md)의 "출시용 자체 모델"에 있습니다.

## 7. 콘텐츠 보안 정책(CSP)

`vercel.json` 에 기본 보안 헤더는 있지만, 스크립트를 어디서 받을 수 있는지 제한하는 정책은 없습니다. `index.html` 의 인라인 스크립트와 외부 서비스(YouTube, Turnstile, Vercel Analytics)를 모두 허용하도록 정책을 짜고 충분히 확인한 뒤 적용합니다.

## 8. 화면 자동 테스트

지금은 계산과 규칙(단위 테스트), 권한(DB 테스트)만 자동으로 검증합니다. 로그인, 운동 완료, 그룹 참여 같은 주요 흐름을 브라우저로 자동 확인하는 테스트(예: Playwright)를 추가합니다.

## 9. 근육 지도

6번의 자체 모델로 앞뒤 근육 지도 이미지를 만들어, 이번 주에 쓴 근육을 홈이나 주간 리포트에 보여 줍니다 (참고 앱 Fleek 의 운동 요약 화면).

- 방식: 앱에서 3D 를 돌리지 않고, 근육 부위별로 렌더한 정지 이미지를 겹쳐 보여 줍니다. 앱이 가벼운 상태를 유지합니다.
- 필요한 것: 운동마다 쓰는 근육 목록 (6번에서 영상을 만들 때 함께 정함)
- 시작 조건: 6번의 자체 모델과 근육 부위 나누기가 끝난 뒤

## 10. 언어 기능 (한국어, 영어)

출시(MVP)에 꼭 필요한 기능은 아니라 우선순위는 낮지만, 앱 화면은 2026-11-18 에 먼저 만들었습니다.

- 완료: 설정과 첫 로그인 화면에서 한국어, 영어 선택 (기본값 한국어). 앱의 모든 화면 문구, 오류 안내, 확인 창, 소개 페이지, 로딩 화면, 개인정보 처리방침과 이용약관 영어판. 서버가 보내는 한국어 오류도 영어로 바꿔 보여 줌
- 남은 일
  - 푸시 알림 문구 (리마인더, 응원): 서버가 보내서 받는 사람의 언어를 모름. 언어를 서버(프로필)에 저장하고 Edge Function 이 골라 보내야 함
  - Supabase 인증 메일 (가입 확인, 비밀번호 재설정): 대시보드의 메일 양식이 한 가지라 한국어로만 나감
  - 앱 설치 이름과 설명 (`manifest.webmanifest`), 아이폰 시작 이미지: 한 가지만 둘 수 있어 한국어
  - 플레이스토어 영어 등록 정보 (2번과 함께)
- 고칠 때: 문구를 넣거나 바꾸면 `src/lib/i18n.en.js` 에 영어를 함께 적음 ([개발 규칙](CONVENTIONS.md) 1절)
